Одно испытание запускает vulnerable, затем protected. Detector ищет подозрительное поведение по access-логам; Control проверяет эффект атаки и верность инцидентов.

Компоненты

Оба режима используют один Shop API. Две записи Gateway/Shop одного requestId описывают один запрос. Подготовка БД и генератор находятся в Control.

Запуск требует Idempotency-Key. Тело: families и необязательный seed. Только два фиксированных профиля; параметры trial после создания неизменяемы. Пока отчёт не сохранён, GET report возвращает 409.

X-Request-Id связывает Runner, логи и incident. X-Forwarded-For передаёт IP виртуального клиента: Gateway доверяет только генератору, Shop только Gateway. RunId задаётся служебным Runtime API.

Shop API генерируется без автоматического запуска Bean Validation: protected применяет нормативные проверки, vulnerable допускает учебные нарушения quantity/quotedTotal.

LogBatch содержит producer и entries; ACK подтверждает хранение в Detector. req_hash учитывает method, исходный path с query и полное тело; если тело недоступно, hash=null. Исходные тела, JWT и пароли не сохраняются.

JSONL возможен как локальный формат файла. Межсервисная доставка - HTTP/JSON напрямую в Detector.

Барьер перед отчётом

Control сначала дожидается completion Runner и сохранения attempts. Timeout клиента не доказывает остановку SQL. Пропуск записи, смена instanceId и deadline дают INCONCLUSIVE.

FINISHING принимает только sequence в объявленных границах; COMPLETED/FAILED - только идентичные сохранённые повторы. Противоречащие сохранённым записям границы дают 409.

Состояния

Trial: PREPARING → RUNNING → FINALIZING → COMPLETED
Альтернативы: FAILED / CANCELLED / INCONCLUSIVE
Runtime: PREPARED → OPEN → CLOSING → CLOSED; либо ERROR
Detector: ACCEPTING → FINISHING → COMPLETED; либо FAILED

CLOSED означает inFlight=0 и окончательный lastSequence. Новый запуск и сброс БД запрещены при cleanupSafe=false. После отмены/ошибки возможен частичный отчёт; отсутствующий run не считается выполненным.

Detector и Evaluator

Detector

Видит HTTP-признаки без режима и эталона. Возвращает итоговый incident с requestIds, description и необязательным family. Инцидент - подозрение на попытку.

Evaluator в Control

Использует приватный план, snapshot, attempts и readonly Shop. Оценивает эффект и TRUE_POSITIVE/FALSE_POSITIVE/UNASSESSED. Ошибка классификации не отменяет обнаружение попытки.

Общий TrialReport содержит cases с episodeId/detection и оценённые incidents обоих режимов. Дашборд вычисляет ASR, precision, recall и FPR. 0/0 = N/A; незавершённый анализ даёт incidents=null, а detection у cases - INCONCLUSIVE. Заблокированная попытка тоже может быть TRUE_POSITIVE.

detection вычисляется на episode по оценённым инцидентам: подтверждённая связь даёт DETECTED/FALSE_POSITIVE; MISSED/CLEAN требуют полных шагов и логов. Связанный TP несовместим с MISSED. Точные правила.
