# Каталог активов API Security Lab

В разделе перечислены активы проекта, их состав, правила доступа, инварианты и последствия нарушения защиты. Инварианты - условия, которые должны сохраняться в защищённом API. В уязвимом API часть из них намеренно нарушается для демонстрации атак.

## Пользователи и доступ

| Актив | Состав | Допустимый доступ | Инварианты | Последствия нарушения |
|---|---|---|---|---|
| **Учётные записи** | Идентификатор пользователя, логин и хеш пароля. | Вход по логину и паролю; хеш использует обработчик входа. | Идентификатор и логин уникальны. Неверные учётные данные не позволяют получить JWT. Хеш не возвращается через API. Превышение заданного политикой лимита попыток приводит к ограничению входа. | Захват чужой учётной записи через credential stuffing. Ограничение попыток не исключает вход по первой верной паре логин-пароль. |
| **Профили** | Идентификатор владельца и сведения о пользователе. | Покупатель читает разрешённые поля своего профиля. | Профиль связан с существующей учётной записью. Его владелец совпадает с пользователем запроса; защищаемые поля чужого профиля не возвращаются. | Раскрытие чужих сведений. |
| **Токены доступа** | JWT с идентификатором пользователя и сроком действия. | Клиент получает токен после входа и предъявляет его при обращении к API. | Подпись токена действительна, срок не истёк. Пользователь запроса определяется по проверенному JWT; переданный клиентом идентификатор не меняет его. Действующий JWT допускает несколько запросов. | Действия от имени другого пользователя. |

## Покупка

| Актив | Состав | Допустимый доступ | Инварианты | Последствия нарушения |
|---|---|---|---|---|
| **Каталог и цены** | Идентификаторы и описания товаров, серверные цены и признак публикации. | Покупатель читает опубликованные товары; цены задаёт сервер. | Цена товара больше нуля. Выдача содержит только опубликованные товары независимо от текста поиска. Переданная клиентом цена не заменяет серверную. | Занижение стоимости покупки или раскрытие неопубликованных товаров через injection. |
| **Корзины** | Владелец, товары, количества и выбранный купон. | Покупатель читает и изменяет свою корзину. | Владелец совпадает с пользователем запроса. Позиции ссылаются на существующие товары; количество каждой позиции - целое число больше нуля. Недопустимый запрос не меняет корзину. Оформление разрешено только для непустой корзины. | Изменение чужой корзины, недопустимое количество товара или оформление пустой покупки. |
| **Купоны** | Код, размер скидки, срок действия, общий лимит и число использований. | Покупатель передаёт код; сервер проверяет применимость и учитывает использование при успешном оформлении заказа. | Купон действует на момент оформления. Число использований - целое число от нуля до общего лимита для всех пользователей включительно, в том числе при одновременных запросах. На заказ применяется не более одного купона. Применённая скидка неотрицательна и не превышает сумму до скидки. Создание заказа с купоном увеличивает счётчик ровно на один; неуспешное оформление не расходует лимит. | Недопустимая скидка, превышение лимита или его расходование без заказа. |
| **Заказы** | Владелец, позиции, количества, зафиксированные цены, скидка и итоговая сумма. | Покупатель читает свой заказ по ID; состав и стоимость фиксирует сервер при оформлении. | Владелец - пользователь, оформивший заказ; чтение разрешено только ему. В заказе есть хотя бы одна позиция; количества - целые положительные числа. Сумма до скидки равна сумме произведений серверных цен на количества, зафиксированных при оформлении; итог равен этой сумме за вычетом скидки и неотрицателен. Повторное или одновременное выполнение одной операции создаёт не более одного заказа и учитывает купон не более одного раза. | Чтение чужих заказов, подмена суммы, повторное создание заказа или списание купона. |
