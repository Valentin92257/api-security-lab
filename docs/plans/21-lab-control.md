# План задачи #21: ADR runner и создание эксперимента

Основание: [задача #21](https://github.com/Valentin92257/api-security-lab/issues/21),
[ADR-0001](../adr/0001-runner-inside-control.md), [Control API](../../contracts/control-api.openapi.yaml)
и [правила контрактов](../../contracts/semantics.md).

## План

1. Описать в ADR runner внутри Control: границы модулей, отдельный executor,
   лимиты, отмену, сохранение attempts и порядок завершения.
2. Добавить PostgreSQL для Control с двумя таблицами: trial с ключом идемпотентности
   и один слот исполнения. Запускать официальный образ Flyway отдельным init job,
   SQL хранить в `db/control/migrations`, приложению выдать
   runtime-роль без DDL. Данные сохранять в Docker volume.
3. Реализовать создание trial, чтение по ID, список с пагинацией и каталог families
   по существующему OpenAPI. На границе API использовать сгенерированные DTO,
   проверять вход, Operator Bearer и возвращать ошибки Problem с `Cache-Control: no-store`.
4. Создавать trial, ключ и резервировать слот в одной транзакции. Прежний ключ
   с теми же параметрами возвращает 200 до проверки слота; изменённые параметры
   или новый ключ при занятом слоте дают 409. Новый trial получает PREPARING и 202.
   Если seed не передан, выбрать его один раз. При старте Control помечать
   прерванный trial как INCONCLUSIVE с `cleanupSafe=false`, сохраняя ключ и слот.
5. Добавить примеры в README и проверить API на PostgreSQL: валидацию, идемпотентность,
   конкурентные запросы, rollback и права runtime-роли. Проверить сборку, миграции
   и сохранение данных после пересоздания контейнеров.

## Границы задачи

Исполнение сценариев, Fixture, Runtime/Detector-клиенты, evaluator и UI подключаются
следующими задачами. Сейчас trial остаётся PREPARING с нулевыми счётчиками и занимает слот.
Автоматическое продолжение, отмена и безопасное освобождение слота ещё не реализованы.
Для известного trial отмена возвращает 503, чтение отчёта - 409.

## Результат проверки

Сборка Control прошла: health-тест и 37 интеграционных проверок на PostgreSQL 17
завершились без ошибок и пропусков. Docker-образ и Compose проверены при реализации
каркаса. Миграция применяется повторно; после рестарта Control и пересоздания
контейнеров с прежним volume сохраняются trial, ключ и занятый слот.
Переход V1 -> V2 проверен на БД с созданным trial: Flyway применяет только V2,
повтор создания возвращает тот же trial, занятый слот сохраняется.
Generated Java и код соседних приложений не изменились.
