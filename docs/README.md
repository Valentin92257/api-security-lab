# API Security Lab

Документация согласована с итоговыми контрактами на 25 октября 2026 года. Машиночитаемый источник: [contracts/README.md](../contracts/README.md). Реализации сервисов и измерения ещё предстоят; в репозитории настроена генерация Java-интерфейсов и DTO.

Локальный учебный стенд сравнивает vulnerable и protected версии API магазина. Пользователь выбирает одно или несколько из пяти семейств атак. Control запускает оба режима с одинаковыми исходными данными, Detector ищет подозрительное поведение по access-логам, а Control независимо проверяет эффект атак и верность инцидентов.

## Команда

| Роль | Ответственность |
|---|---|
| Р1. API и данные | Два режима Shop, транзакции, access-логи, данные для подготовки БД и независимой проверки |
| Р2. Защита | Gateway, JWT, профили vulnerable/protected, лимиты, access-логи и Runtime API |
| Р3. Атаки | Модуль Runner внутри Control, планы, виртуальные IP, seed, исполнение и отмена |
| Р4. Detector и дашборд | Detector, Control, подготовка БД, orchestration, evaluator, UI и отчёты |

Четыре приложения: shop-api, lab-gateway, lab-detector, lab-control. Shop запускается дважды. Generator и подготовка БД - внутренние модули Control. Р1 поставляет данные и SQL-адаптеры, Р2 - управление приёмом запросов, Р3 - интерфейсы исполнения и сохранения результатов.

## Объём и границы

Магазин предоставляет регистрацию, login, профиль, поиск, корзину, установку количества/купона, создание и чтение заказа. Истории заказов, платежей, возвратов и универсального выполнения чужого кода нет. Испытание всегда сравнивает два фиксированных режима; пользователь не настраивает отдельные политики через API.

JWT многократен. Однократность checkout обеспечивается версией корзины и идемпотентностью. Первая корректная пара credentials и новые допустимые действия с украденным bearer остаются рисками модели. Detector может ошибаться или не обнаружить попытку, которую невозможно отличить от легитимного поведения по HTTP-признакам.

Shop/Gateway отправляют логи прямо в Detector по HTTP/JSON. Control получает только итоговые инциденты и проверяет эффект по ответам и readonly состоянию БД. Перезапуск, потеря логов и превышение deadline дают INCONCLUSIVE; продолжения старого прогона нет.

## SQL и модели данных

[docs/data](data/README.md) содержит действующие SQL-черновики и ER магазина: семь таблиц в каждой из двух shop DB. Физическое хранение Control и Detector определяется при реализации и не является HTTP-контрактом. Отменённая схема общих audit/jobs/view хранится отдельно как [исторический материал](data/legacy-lab/README.md) и не применяется при запуске.
